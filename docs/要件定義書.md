# SUISEN 要件定義書

作成: 2026-10-06

## 1. 目的

- 北九州高専の1〜2年生のうち、コース選択に迷う学生を少なくする。
- 学生が自分に合ったコースを選べるよう手助けする。

### 背景

情報コースの授業で行うアプリ開発コンペの作品として作る。実際の運用は予定していないため、実データが手に入らない部分はテストデータで代わりにする。

### 成功の判断

実際にアプリを使ってみて、利用者に合ったコースと進路が出てくれば成功とする。

## 2. 対象ユーザー

北九州高専 生産デザイン工学科の1〜2年生（2年後期のコース分け前の学生）。

選べるコースは次の5つ。

- 機械創造システム
- 知能ロボットシステム
- 電気電子
- 情報システム
- 物質化学

## 3. アプローチ

1. 学生のデータを集める（チャット、将来的には Google フォームも使う）。
2. 集めたデータを、コースの特徴や先輩の進路と比べる。
3. 結果を診断結果としてまとめて学生に返す。
4. 利用者のデータを保存して蓄積し、後の学生への推薦や進路紹介に活かす。

## 4. 開発範囲

KISS の原則に従い、最初はメイン機能のチャットだけを作る。

| 区分 | 機能 |
| --- | --- |
| 今回作る | チャット（F1）、コース推薦（F2）、進路紹介（F3）、診断結果（F4）、ログイン（F5）、会話の保存（F6）、資料の検索（F7、2026-10-12 追加） |
| 後で作る | Google フォームでのデータ収集（3〜5年生へのアンケートを含む）、蓄積したデータの推薦・進路紹介への活用 |

## 5. 機能要件

| ID | 機能 | 内容 |
| --- | --- | --- |
| F1 | チャット | 学生と会話して、興味や得意なこと、学び方の好みなどの特徴を聞き出す |
| F2 | コース推薦 | チャットで分かった学生の特徴を、5コースの特徴と比べて、最も合うコースを推薦する |
| F3 | 進路紹介 | 学生に似た先輩の進路（就職先・進学先）を探し、AI が文章にしてチャットで返す |
| F4 | 診断結果 | 学生に最も合うコースを表示する |
| F5 | ログイン | 利用者を識別する |
| F6 | 会話の保存 | 会話の内容と診断結果を利用者ごとに保存し、蓄積する |
| F7 | 資料の検索（RAG） | シラバスなどの資料を検索し、見つかった内容をもとに AI に答えさせる |

### F1 チャット

- 北九州高専の学内 LLM を使って会話する。
- 推薦と進路紹介に必要な情報を聞き出すことを目的にする。
- 聞き出す特徴は、コースの特徴データと同じ物差しにする。
  - 9つの興味分野：力学・材料、熱・流体、設計・ものづくり、制御・ロボット、回路・電子、電力・電気機器、プログラミング・情報、化学、生物・食品
  - 4つの学び方：手を動かす、コード、理論、実験

### F2 コース推薦

- コースの特徴には、高専 Web シラバス（令和8年度）から作った既存のデータを使う。
  - `data/syllabus/subjects_2026.csv`（開講科目一覧）
  - `data/syllabus_raw/`（シラバスの元の HTML）
  - vault の `Dev/2026-10-06-kitakyushu-kosen-courses-syllabus.md`（興味分野9つ・学び方4つでのコースの数値化と、比べ方の教訓）
- コースの特徴データにないことは推測で答えない。

### F3 進路紹介

- 過去の先輩のデータを使い、学生に特徴が似た先輩がどのコースに進み、卒業後どんな進路に進んだかを示す。
- 先輩のデータにないことは推測で答えない。
- 先輩のデータは今回はテストデータを作って使う。
  - 実データは入手方法がないため。
  - 将来は、Google フォームで今の3〜5年生にアンケートをとって集める想定。
  - テストデータは、実データと同じ形（同じ項目）にしておき、後から差し替えられるようにする。
- 先輩のデータの項目は、学生の特徴と同じ項目（9つの興味分野と4つの学び方）に、「進んだコース」と「進路（就職先・進学先）」を足したものにする。
- テストデータは100件（各コース20件）作る。

### F4 診断結果

- 最初は「最も合うコース」を1つ表示するだけにする。
- ログイン後のホーム画面に、その時点の利用者のステータスとして表示する。

### F5 ログイン

- 最初から作る。会話を利用者ごとに蓄積するため。
- 学生の区別には、学校から配られている Google アカウントのメールアドレス（`@apps.kct.ac.jp` で終わるもの）を使う。
  - Google アカウントでのログイン（Google の認証）は使わない。メールアドレスは、学生を区別する ID として使うだけ。
  - `@apps.kct.ac.jp` で終わらないメールアドレスは受け付けない。
- 本人確認はメール認証で行う。入力されたメールアドレスに確認コードを送り、受け取った本人だけがログインできるようにする。
  - 2026-10-12 から一時的に外していたが、アプリ専用の Gmail アカウントを用意し、2026-10-13 に有効にした。
  - 確認コードは6桁の数字で、有効期限は10分。
  - 確認メールは、アプリ専用の Gmail アカウントから送る（Gmail の SMTP とアプリパスワードを使う）。
- 一度ログインしたら、1週間はログインしたままにする。

### F6 会話の保存

- 最初から作る。蓄積したデータを後の推薦や進路紹介に活かすため。
- 今回は保存して蓄積するところまで作る。蓄積したデータを推薦や進路紹介に使う機能は後で作る。

### F7 資料の検索（RAG）

2026-10-12 追加。

- **背景：** 学内 LLM は自分で調べられないため、知らないことをもっともらしく作って答えること（ハルシネーション）が多い。
- **方針：** 質問に関わる資料をアプリが検索し、見つかった内容を LLM に渡して、それをもとに答えさせる。資料にないことは「分かりません」と答えさせる。
- **検索する資料：** 高専 Web シラバス（令和8年度）の5コースの専門科目。
- **使う場面：**
  - F1 チャット：コースや授業について聞かれたとき。
  - F2 コース推薦：推薦したコースで、学生の興味に関わる授業を添える。
  - F3 進路紹介：先輩の進路につながる授業を添える。
- 答えの根拠にした資料（科目名）を、学生が分かるように示す。

## 6. 非機能要件

- **LLM:** 北九州高専の学内 LLM（OpenAI 互換の API）を使う。
- **動かす場所:** 学内 LLM は学内ネットワークからしか使えないので、アプリも学内ネットワーク上で動かす。
- **形式:** Web アプリとして作る。
- **対応端末:** PC とスマホ（2026-10-13 にスマホのレイアウトを追加。学内 Wi-Fi につないだスマホのブラウザから使う）。

## 7. 対象外（今回は作らないもの）

- Google フォームでのデータ収集
- 診断結果のグラフなど、最も合うコース以外の表示
- 進路と関係のない悩みの相談
- 実際の先輩のデータの収集
- 蓄積したデータを推薦や進路紹介に使うこと
